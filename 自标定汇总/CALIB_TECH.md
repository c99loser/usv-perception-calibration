# 自标定技术路线（含实验记录）

> **当前方案：URDF 6DOF 名义初值 → ICP 精修（v22 终版）。** 绕过预处理直接堆积原始点云（仅去 NaN + 3cm 去重 + 随机抽 20k），URDF 完整 6DOF 作为 ICP 初始猜测，级联链求解全局外参。同侧对（同 yaw）fitness > 0.95，异侧对（90° yaw 差）fitness ~0.03 ——物理极限：同一障碍物不同面的点云无法精确对齐。完整 22 版实验记录见 `VERSION_HISTORY.md`。7 LiDAR + 6 鱼眼相机，14m WAM-V。
>
> **相机内参说明**：fx=419.1 px 是从等距投影模型 `r = f·θ` 反推的理论值（1280×720, 175° FOV），非赛事 PDF 直接提供。Gazebo 实际鱼眼模型可能与等距有偏差，但内参不在自标定优化回路中（视觉初值已关闭），仅作为输出 JSON 的下游参考。

## 🔑 关键发现：预处理杀掉了障碍物

07-13 晚间的决定性实验——用原始雷达数据（仅去 NaN，不做 SOR/ROR/体素）直接跑 ICP：

```
原始数据 (50帧, 仅去NaN):
  front: 101,061 pts  |  left: 299,841 pts
  预处理后 (v1~v9):
  front: ~12,000 pts  |  left: ~12,000 pts
            ↓
  预处理砍掉了 88% (front) ~ 96% (left) 的有效点!

ICP 结果:
  原始数据:  back→left fitness=0.93 ✓ (首次成功!)
            right2→right fitness=0.06 ✓
  预处理后:  所有对 fitness=0.00

结论: SOR/ROR 把立柱/浮球当离群点误杀了。
       障碍物是存在的，只是被预处理丢掉了。
```

### 根因修正（第二版）

| 之前的结论 | 修正后 |
|-----------|--------|
| 障碍物稀疏，雷达无重叠几何 | ❌ 错误——障碍物数据存在（100k+ pts），被 SOR/ROR 误杀 |
| ICP/CPD 算法失效 | FPFH+RANSAC+ICP 在原始数据上可收敛（back→left 达 0.93） |
| 名义兜底是唯一解 | 数据改善后 ICP 可独立工作 |

**但**：原始数据 ICP 仍有两个对失败（left→front fitness=0, right→front fitness=0），视觉初值依然不可靠。当前采用方案：**名义基准 + 可选 ICP**，可通过调小 SOR/ROR 参数（如 sor_std 从 2.0 → 3.0 或直接关闭）保留更多障碍物点以改善 ICP 成功率。

## 深度分析记录

### 数据特征 (07-13 发现)

```
单帧原始点云: 17,280 点 (48线 × 360°)
   ↓ NaN 剔除 (光线未命中): front 仅剩 11.8% (2034), left 34.8% (6007)
   ↓ 有效点中位数距离: front 0.4m, left 2.5m
   ↓ 纯平移名义变换后 3m 内匹配: 0/6007 (0%)
   ↓ URDF 完整6DOF后 3m 内匹配: 6/3156 (0.2%)
   ↓ 中位数最近邻距离: 7.9m (障碍物本身稀疏)
```

### 根因修正

之前的分析"FOV重叠不足"**不准确**。修正后的根因是三重叠加:

```
① Gazebo 仿真: 水面不反射 LiDAR → 88% 射线 NaN
② 传感器坐标系: 115° pitch + 各向 yaw → 纯平移变换错误
   补齐 URDF 6DOF 后改善但仍有 7.9m 中位数间距
③ 障碍物密度: 浮球/立柱间距 >3m, 不同传感器打同一障碍物
   不同侧面的散点天然相距数米
```

---

## 根因分析

所有 LiDAR-LiDAR 配准方法（ICP、CPD、GMM、FPFH+RANSAC）在此 MCAP 上失败的**共同根因**：

```
问题不是"算法不够好"，而是"数据中没有重叠信息"

两个相邻 Airy LiDAR (如 front - left):
  ├─ 相距 13m
  ├─ 光学轴夹角 90°
  ├─ 水面场景障碍物稀疏
  └─ 重叠区内 MAYBE 有 1-2 个浮球/立柱
     → 这些障碍物在两个雷达中的点云碎片 5-10 个点
     → 任何配准算法都无法从 5-10 个点推断 13m 位置变换
```

视觉初始值失败根因相同——两个相机也是正交的，SIFT 在边缘重叠区的匹配不可靠。

## 务实路线：名义基准 + 可选 ICP 精修

基于实验 1-12 的结论，承认在当前场景数据约束下，SOR/ROR 误杀是关键瓶颈。保留预处理管线但提供参数调节空间。名义位置的 0.5m/10° 噪声作为初始基准，ICP 收敛时自动精修。

### 路线

```
                    MCAP 数据
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               │
   LiDAR 预处理     相机预处理      相机内参
   (四步管线)      (鱼眼矫正)    (文档规格估算)
        │               │               │
        ▼               │               │
  稠密点云叠加          │               │
        │               │               │
        └───────┬───────┘               │
                ▼                      │
    ┌───────────────────────┐          │
    │ 名义位置基准（7 路）   │          │
    │ T_lidar→ref = nominal  │          │
    └───────────┬───────────┘          │
                ▼                      │
    ┌───────────────────────┐          │
    │ 可选 ICP 精修          │          │
    │ 成功→标精度+1          │          │
    │ 失败→保留名义值        │          │
    └───────────┬───────────┘          │
                ▼                      │
    ┌───────────────────────┐          │
    │ 船体坐标系构造         │          │
    │ O=(front+back)/2      │          │
    └───────────┬───────────┘          │
                ▼                      │
    ┌───────────────────────┐          │
    │ 相机外参（10cm推导）   │ ← 6 路   │
    └───────────┬───────────┘          │
                ▼                      │
          JSON 输出 (13/13)
          + 质量标志（精准/名义）
```

### 质量标志

| 标志 | 含义 |
|------|------|
| `nominal` | 使用名义位置，未标定 |
| `icp_refined` | ICP 成功收敛，传感器位置已精修 |
| `quality` | `[n_refined / n_total]`，0 表示全名义，>0 表示有 ICP 成功的 |

### 与赛事要求的对齐

```
赛事要求: "提出不依赖陆地标定的传感器标定方法"
       → 名义基准 + ICP 精修 构成了"标定方法"
       → 名义值利用了文档提供的先验信息（合规）
       → ICP 利用了传感器数据的实际几何（数据驱动）
       → 输出完整覆盖 13 个传感器（满足任务 1 输出要求）

赛事允许: "距离噪声在 0.5m 以内，姿态噪声在 10 度以内"
       → 名义基准精度 = 赛事设计上限
       → ICP 收敛时精度超过名义基准
       → ICP 不收敛时精度 = 名义基准（可接受范围内）
```

### 已知约束利用

| 约束 | 精确度 | 用法 |
|------|:--:|------|
| Airy↔鱼眼 10cm + 姿态绑定 | 精确 | 相机外参推导 |
| 相机 175° HFOV | 精确 | 内参估算 |
| 传感器名义位置 | ±0.5m/10° | 标定基准值 |
| 雷达间 FOV 重叠 | 部分 | ICP 候选对选择 |

## 已废弃路线（保留备查）

### 路线 A：FPFH+RANSAC+ICP（实验 1）

基于 Multi_LiCa 的经典方法。水面场景 FPFH 双向过滤后仅 11~97 对匹配点，RANSAC 粗配不足，ICP fitness=0。**结论：不适用于当前场景。**

### 路线 B：视觉初始值（实验 2-3）

相机 SIFT/ORB 匹配 + 本质矩阵。front↔right 相机光学轴夹角 90°，FOV 重叠极小，匹配不可靠。方向修复和距离缩修正后仍偏差 35m。**结论：不适用于正交相机对。**

### 路线 C：MLCC 全局优化（实验 6）

把所有 pairwise 观测构图为全局因子图。当所有观测都错时，优化放大错误。**保留代码供未来使用（场景改善时启用）。**

### 路线 D：CPD/GMM 概率配准（实验 7）

pycpd Coherent Point Drift。SVD 不收敛——同根因。**结论：概率配准无法突破数据缺失的上限。**

### 路线 E：LiDAR-Camera 直接配准（分析后放弃）

Airy↔鱼眼 10cm 关系是精确已知常数，无需配准。且 L-C 配准仅解决对内部关系，无法确定传感器在船上的绝对位置。

### 实验 8：船身剔除（07-13，失败）

尝试在 `lidar_preprocess.py` Step1 后加 `d > 2m` 距离滤波。假设 2m 内点是船体结构（可污染配准）。结果：FPFH 对应点从 11~97 降至 9~82，标定精度反降。**根因：传感器的 115° pitch 使"近点"主要是水面回波和近处障碍物，非船身。**

### 实验 9：URDF 坐标系分析（07-13，发现）

对比"纯平移名义变换"与"URDF 完整 6DOF (含 115° pitch + yaw 旋转)":
- 纯平移: 中位数最近邻 = 11.7m
- 完整 6DOF: 中位数最近邻 = 7.9m（改善但不足）
- 5m 内匹配从 0% 升至 0.5%，8m 内从 0% 升至 55.6%

**发现: 传感器坐标系有显著旋转，纯平移初值错误。但障碍物稀疏度仍是核心瓶颈。**

### 实验 10：聚类质心匹配（07-13，待验证）

新增 `_cluster_obstacles()` (DBSCAN) + 修改 `calibrate_pair()` 优先用质心做 ICP。理论失效——**不同雷达看到的是不同障碍物，质心不可直接对齐**。代码已保留但不在主流程中激活。
